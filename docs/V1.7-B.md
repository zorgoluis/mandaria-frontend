# Mandaria Web V1.7-B — Dispatch Visibility & Provider Claiming

## Alcance

Mandaria Web permite probar operacionalmente el flujo V1.7:

```text
Quote ACCEPTED → Dispatch OPEN → PROVIDER_ADMIN ve el servicio → TOMAR SERVICIO → backend decide → CLAIMED
```

No asigna Driver ni Vehicle (V1.8), no usa sockets (actualización manual, refetch e invalidación de consultas) y no modifica reglas financieras.

Fuente del contrato: Mandaria Backend V1.7.0 (`docs/openapi.json` 1.7.0, `src/dispatch/*`: controllers, `dispatch.dto.ts`, `dispatch.responses.ts`, `dispatch.select.ts`, `dispatch-policy.ts`, `dispatch.service.ts`), inspeccionado el 2026-09-16. No se modificó backend ni Coita Eats.

## API consumida

| Método y ruta                                                      | Uso en la web                                                                                           |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| GET /provider/dispatches?providerId=&view=&status=&page=&pageSize= | PROVIDER_ADMIN. `view=AVAILABLE` (Disponibles), `CLAIMED` (Mis servicios), `ALL` + `status` (Historial) |
| GET /provider/dispatches/:dispatchId?providerId=                   | Detalle según `access` (`OFFER`, `OWNER`, `SUMMARY`)                                                    |
| POST /provider/dispatches/:dispatchId/claim?providerId=            | Sin body. El proveedor nunca viaja en el payload                                                        |
| POST /provider/dispatches/:dispatchId/release?providerId=          | `{reason}` 3–500 caracteres (texto libre)                                                               |
| GET /admin/dispatches?status=&deliveryRequestPublicId=&page=       | SUPER_ADMIN, auditoría de sólo lectura                                                                  |
| GET /admin/dispatches/:dispatchId                                  | SUPER_ADMIN, candidatos, liberaciones y cancelación                                                     |

No hay endpoints de claim/release para SUPER_ADMIN, ni de creación de Dispatch: se abre al aceptar la Quote.

## Disponibles y dinero

Cada tarjeta muestra zona, tipo de servicio, estado, tiempo restante, origen, destino, distancia, duración estimada y un bloque de dinero con dos áreas separadas y de distinto color:

- **Costo del envío**: `service.deliveryFee` (precio congelado de la Quote).
- **Valor de mercancía**: `service.goods.value` con su modalidad traducida (Mercancía prepagada / Adelanto por repartidor). Con `driverAdvancesGoods` se muestra el aviso "El repartidor adelanta $X al recoger." Nunca se suman.

`access: SUMMARY` no trae `service`: la tarjeta explica el motivo con campos reales (tomado por otro, expirado, cancelado o liberado por mi proveedor) y no ofrece acciones.

## Tomar servicio

1. **TOMAR SERVICIO** sólo aparece con `access: OFFER`, `status: OPEN` y candidatura `OFFERED`; se deshabilita cuando la cuenta regresiva llega a cero.
2. Confirmación con origen, destino, ruta, costo del envío y mercancía/adelanto.
3. Si la ventana terminó mientras se confirmaba, no se envía la petición.
4. Sin propiedad optimista: la tarjeta no cambia hasta la respuesta. Éxito → "Servicio tomado correctamente.", refetch y paso a Mis servicios.
5. Resultados finales del backend (`DISPATCH_ALREADY_CLAIMED` → "Este servicio ya fue tomado por otro proveedor.", `DISPATCH_EXPIRED`, `DISPATCH_CANCELLED`, `DISPATCH_RECLAIM_NOT_ALLOWED`, `PROVIDER_NOT_ELIGIBLE`, 404) cierran el formulario con el mensaje y refrescan la lista. 400, 429, 500 y red dejan el diálogo para reintentar.

## Liberar servicio

Sólo para `access: OWNER`, `status: CLAIMED` y `claimedByMe`. El diálogo advierte "Si liberas este servicio, no podrás volver a tomarlo." y pide motivo: tres opciones predefinidas o "Otro" con texto libre; se envía únicamente el texto (3–500 caracteres, validado antes). Éxito → "Servicio liberado." y refetch; el servicio sale de Mis servicios y no vuelve a Disponibles para ese proveedor. `DISPATCH_NOT_CLAIMED_BY_PROVIDER` se muestra como resultado final.

Tras tomar un servicio sólo se informa que la asignación de repartidor y vehículo llegará en una próxima etapa; no hay botones de asignación.

## Seguridad

- Rutas protegidas por rol en el router y backend como autoridad (`403` para SUPER_ADMIN, DRIVER e IntegrationClient en rutas de proveedor).
- El proveedor sale del selector existente basado en las memberships propias (`/provider/profiles`, `/provider/profile`). Con varias memberships se exige elegir; `providerId` en la URL sólo selecciona y el backend responde 403 si no hay membership. Un Dispatch ajeno responde 404 y la UI no revela nada.
- Claim sin body; el backend rechaza cualquier campo (400).
- La cuenta regresiva es informativa, nunca un control de seguridad.
