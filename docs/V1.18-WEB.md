## Contratos y privacidad

Base central `${VITE_API_URL}/api/v1`, una sola vez. Titular CUSTOMER:

- GET `/customer/delivery-requests/:publicId/location`.
- GET/POST `/customer/delivery-requests/:publicId/tracking-link`.
- POST `.../tracking-link/revoke`.
- GET `.../tracking-link/attempt?operation=ISSUE|REVOKE&expectedLinkRevision=...`.

Mutaciones con UUID nueva por intención, Idempotency-Key y `{expectedLinkRevision}`. Consulta con UUID original. No existe `/close` para este contrato.

Destinatario: GET `/shared/delivery-tracking`, `Authorization: Tracking selector.secret`, mediante transporte separado sin JWT humano, refresh, cookies, referrer ni caché. Se consume y borra el fragmento antes de importar la aplicación; también se admite reapertura del enlace en la misma pestaña. Se conserva sólo en memoria; navegar fuera/recargar obliga a abrir el enlace original. Ninguna consulta pide geolocalización del destinatario. El proyecto no registra service worker ni analítica.

URL de emisión sólo en memoria del componente, fuera de TanStack Query. Se retira al cerrar, ocultar la pestaña, navegar/cambiar actor o alcanzar expiración; terminal oculta el enlace. Una respuesta tardía después de desmontar no vuelve a mostrarlo. La copia requiere pulsar el botón: el portapapeles queda bajo control del usuario y no se lee ni borra automáticamente.

Marcador local `mandaria.tracking.pending.v1`: únicamente actor, publicId, ISSUE/REVOKE, key y expectedLinkRevision. No almacena URL, token, cuerpo ni datos personales. Se escribe antes de POST; fallo de almacenamiento bloquea el envío. Web Locks y bloqueo en memoria evitan doble clic y envío simultáneo desde pestañas cooperantes. Sin Web Locks no se habilita una mutación insegura. Una cuenta distinta conserva el bloqueo, sin consultar ni cerrar intentos ajenos.

## Procedimiento de reconciliación

1. Tras timeout/respuesta perdida, conservar marcador. No asumir fracaso ni repetir emisión.
2. Con el actor original, **Consultar estado e intentos**. Se consultan los recibos y después la metadata vigente.
3. APPLIED_SECRET_UNAVAILABLE: emisión histórica acreditada; el secreto no se recupera. APPLIED_REVOKED: revocación histórica; puede existir un enlace posterior. SUPERSEDED: la revisión original ya no puede aplicar después, sin acreditar ausencia histórica de efectos ni revocación actual. Una vez coherente la metadata, retirar ese marcador. Ninguno emite automáticamente.
4. PENDING_OR_UNKNOWN conserva el bloqueo. Es posible consultar de nuevo o confirmar expresamente **Revocar enlace / cerrar emisión incierta**, con revisión actual y UUID nueva. El marcador original se conserva hasta reconciliarlo; un cierre incierto añade su propio marcador mínimo.
5. El cierre no cancela ni revierte entregas físicas/cobros. Si gana la revocación, el ISSUE tardío no puede aplicar; si hay409, consultar y pedir otra decisión. No se fuerza una revocación sobre una revisión posterior.
6. Timeout/conflicto de mutación deshabilita otra mutación hasta una consulta. Las confirmaciones nunca están preseleccionadas. Estados desconocidos o metadata atrasada conservan bloqueo.
