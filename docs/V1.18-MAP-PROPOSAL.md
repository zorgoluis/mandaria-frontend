# V1.18 — Propuesta cartográfica (sin activación)

## Decisión del propietario: Google Maps (2026-10-06)

La propuesta Leaflet/MapTiler conservada abajo queda como antecedente, **no como recomendación vigente**. Implementado Google Maps JavaScript API, mapa raster, punto circular y círculo de precisión con Circle. No usa Marker obsoleto, AdvancedMarker ni Map ID; tampoco Places, geocodificación, rutas, ETA o historial. Sin nuevas dependencias npm. SDK una sola vez por documento, al existir una muestra autorizada, con timeout15s sin reintento automático. Una instancia por componente visible, actualización de círculos y centro sin reconstrucción; retirada/desmontaje libera overlays, listeners y referencias (Maps no ofrece destructor público del mapa).

### Configuración y publicación (pendiente de clave del propietario)

VITE_GOOGLE_MAPS_API_KEY es opcional y se lee exclusivamente en src/config/env.ts. Copiar .env.example a configuración privada local y completar allí el valor; no pegarlo en documentación, capturas ni mensajes. Reiniciar npm run dev tras cambiarlo. Para publicación, suministrarlo al entorno de npm run build. Dockerfile declara ARG/ENV del mismo nombre junto a VITE_API_URL; el pipeline debe pasarlo como build arg desde su configuración privada. .dockerignore excluye .env*. Cambiar variables del contenedor nginx después del build no modifica JS estático. No se ejecutó Docker ni se leyó ninguna clave real. Sin clave se conserva la posición textual y aparece “Mapa no disponible”.

La clave Web será visible en el bundle y solicitudes Google; no es un secreto backend. Restringirla a Maps JavaScript API y sitios web autorizados (producción https://mandaria.com.mx/*; claves de desarrollo separadas con localhost/127.0.0.1 y puertos necesarios). No reutilizar credenciales de routing ni habilitar otras APIs. Activar facturación/cuotas/alertas conforme al proyecto del propietario; confirmar precios de Dynamic Maps y límites antes de publicación. No se contrataron servicios.

### CSP, referencias y privacidad

nginx.conf contiene una allowlist para raster: scripts maps.googleapis.com/maps.gstatic.com, imágenes de los dominios Google documentados, fuentes Google Fonts. Maps requiere estilos dinámicos: style-src añade unsafe-inline; script-src permite unsafe-eval siguiendo la guía del SDK, **sin unsafe-inline para scripts**. Se conserva connect-src https:/wss: existente para no romper API/orígenes actuales; no se amplió. No se habilitan frames ni workers porque no se usan funciones vectoriales/Street View. Esta es revisión estática y debe verificarse con SDK real; si cambian dominios del SDK revisar la guía, no añadir comodines globales a ciegas. Una CSP con nonces únicos por respuesta es la opción recomendada por Google; requeriría inyección dinámica en el hosting estático y no se simula con un nonce fijo.

Referrer-Policy y meta pasan de no-referrer a origin: nunca incluyen ruta, query ni fragmento, y permiten restricción Web. El script usa referrerPolicy origin y auth_referrer_policy=origin. Las llamadas Tracking conservan su no-referrer propio. main.tsx elimina el fragmento antes de cargar Root; adicionalmente el loader rechaza cualquier hash presente. No preconnect ni SDK en login/portal/sin GPS autorizado. No se envían tokens, cabeceras Mandaria, contactos o MDR al loader ni a opciones del mapa. El SDK recibe sólo coordenadas autorizadas y precisión; la aplicación no solicita geolocalización ni usa analítica/storage para el mapa. La prueba de red usa SDK simulado; falta inspección de solicitudes internas del SDK real.

Actualizar antes de publicar los avisos y términos accesibles a cliente y destinatario: Google como proveedor cartográfico, IP/origen y área visible/coordenadas tratadas para mostrar el mapa, finalidad, enlaces a políticas de Google y términos aplicables; evaluar base legal/consentimiento, transferencias y retención con el responsable de privacidad. No prometer anonimato ni ausencia de tratamiento por terceros. No ocultar logo, atribución, controles legales o copyrights generados por Google. La alternativa textual permanece disponible ante bloqueo/offline; no cachear GPS ni crear mapas offline.

Fuentes oficiales consultadas: [carga del SDK](https://developers.google.com/maps/documentation/javascript/load-maps-js-api), [formas/círculos](https://developers.google.com/maps/documentation/javascript/shapes), [CSP](https://developers.google.com/maps/documentation/javascript/content-security-policy), [restricciones de claves](https://developers.google.com/maps/api-security-best-practices). Ninguna prueba con Google real se declara aprobada.

## Antecedente: propuesta anterior no seleccionada

## Situación y elección propuesta

No hay biblioteca cartográfica en package.json ni claves de mapas en la configuración frontend. El proveedor de routing del backend no implica licencia, clave o autorización para mostrar mapas. La interfaz actual muestra coordenadas, precisión y frescura autorizadas.

Propuesta: **Leaflet con teselas raster de MapTiler**, sujeta a aprobación comercial y de privacidad. Un punto y un círculo de precisión no necesitan un motor vectorial/WebGL. Cargar el componente de forma diferida, mantener una instancia y actualizar únicamente la posición; el polling GPS no debe recrear el mapa. No agregar ETA, navegación ni historial. [Leaflet](https://leafletjs.com/) y [ejemplo oficial MapTiler/Leaflet](https://docs.maptiler.com/leaflet/examples/raster-tiles-in-leaflet-js/).

MapLibre GL JS sería una alternativa si aparecen necesidades vectoriales reales; añade revisión de WebGL, workers y CSP que no aporta valor imprescindible a esta versión. [Documentación oficial](https://maplibre.org/maplibre-gl-js/docs/).

## Configuración propuesta, no aplicada

- Variables opcionales centralizadas en src/config/env.ts para proveedor, estilo y clave pública de mapas. Sin configuración, conservar la presentación textual.
- Claves separadas por entorno, restringidas a los orígenes web autorizados; producción sin comodines ni localhost. La clave de mapas es visible en navegador y no debe confundirse con JWT o secretos de enlaces. No crear ni reutilizar claves de routing.
- Validar Allowed HTTP origins con solicitudes raster crossOrigin anónimas y la política existente no-referrer. No enviar credenciales, identificadores MDR ni tokens de seguimiento al proveedor. [Protección oficial de claves](https://docs.maptiler.com/guides/credentials/api-key/).
- JS/CSS propios dentro del bundle, sin CDN. La CSP actual permite imágenes sólo self/data; sería necesario permitir exclusivamente el origen de teselas elegido. connect-src ya permite https: globalmente; no ampliarlo. Verificar estilos dinámicos de Leaflet bajo style-src self antes de proponer una excepción; no añadir unsafe-inline por defecto. Leaflet raster no requiere iframe ni worker.

## Atribución y privacidad

Mantener atribución visible y accesible de MapTiler y OpenStreetMap, también en móvil, conforme al estilo/licencia contratados. Las solicitudes de teselas revelan IP y zona aproximada por coordenadas de tesela/zoom aunque el marcador se dibuje localmente. Revisar tratamiento, retención, regiones y subprocesadores antes de contratar; no asumir garantías no comprobadas. [Política de privacidad](https://www.maptiler.com/privacy-policy/).

No usar tiles.openstreetmap.org como servicio productivo por defecto: capacidad limitada, sin SLA, restricciones de descargas y requisito de Referer que choca con no-referrer actual. [Política OSM](https://operations.osmfoundation.org/policies/tiles/). Alojamiento propio es posible, con costos y mantenimiento adicionales.

## Fallos y disponibilidad

Sin proveedor o ante error de teselas: estado explicativo y presentación textual de la fotografía aún autorizada. Sin señal: no inventar una posición ni centrar en 0,0. Si falla la consulta GPS, aplicar el comportamiento existente; nunca prolongar coordenadas por tener un mapa cargado. Transferencia, incidencia, terminal y caducidad deben retirar también marcador y círculo. No guardar GPS en almacenamiento persistente, historial ni paquetes offline. Caché de teselas sólo según términos del proveedor, separada de datos GPS.

## Costos y decisión pendiente

Verificar plan comercial, cuotas, límite duro/sobrecosto, alertas, SLA, moneda e impuestos antes de elegir. Con Leaflet externo, comprobar facturación por solicitudes de tesela frente a sesiones de SDK; estimar aperturas, pan/zoom, retina y concurrencia. No equiparar una consulta GPS a una carga de mapa. No se ha contratado servicio ni introducido clave. [Precios vigentes](https://www.maptiler.com/cloud/pricing/) y [sesiones frente a solicitudes](https://docs.maptiler.com/guides/account/sessions-vs-requests/).

Aceptación futura: prueba de CSP/orígenes en hosting equivalente, atribución móvil/teclado, caída del proveedor, retirada inmediata de marcadores y medición de solicitudes/costo con datos sintéticos.
