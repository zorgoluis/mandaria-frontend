# Mandaria Web V1.6-B — Zonas de servicio, tarifas y cotizaciones

## Alcance y contrato

Fuente: Mandaria Backend V1.6.0 (`docs/openapi.json`, `admin-service-zones.controller.ts`, `service-zones.dto.ts`, `service-zones.service.ts`, `admin-rate-plans.controller.ts`, `rate-plans.dto.ts`, `rate-plans.service.ts`, `rate-bands.ts`, `admin-delivery-quotes.controller.ts`, `delivery-quotes.dto.ts`, `delivery-quotes.service.ts`, `geo/geometry.ts`, `common/http-exception.filter.ts` y `common/domain-error.ts`), inspeccionados el 2026-09-15. No se modificó backend ni Coita Eats.

Mandaria Web V1.6 administra **dónde puede operar Mandaria y cuánto cuesta una entrega local**. Todavía **no** administra qué Provider, Driver o Vehicle realizará el servicio (V1.7).

## API consumida

Todas con prefijo `/api/v1`, Bearer humano y `@Roles('SUPER_ADMIN')`. PROVIDER_ADMIN y DRIVER reciben 403.

| Método y ruta                                 | Uso                                                                                                                       |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| GET /admin/service-zones                      | `page`, `pageSize` (1–100), `status` (ACTIVE/INACTIVE), `search` (código o nombre, ≤100). Los items **no** traen boundary |
| GET /admin/service-zones/:id                  | Zona con boundary GeoJSON normalizado y bounding box calculado                                                            |
| POST /admin/service-zones                     | `{code,name,currency,boundary}`. Nace INACTIVE. Código `^[A-Z][A-Z0-9_]{1,49}$`, moneda ISO 4217 inmutable                |
| PATCH /admin/service-zones/:id                | Sólo `{name}` (1–100). Código y moneda son inmutables                                                                     |
| PUT /admin/service-zones/:id/boundary         | `{boundary}` completo. Con la zona ACTIVE responde 409 `SERVICE_ZONE_NOT_EDITABLE`                                        |
| POST /admin/service-zones/:id/(de)activate    | Idempotentes. Activar responde 409 `SERVICE_ZONE_OVERLAP` si toca o interseca otra zona activa                            |
| GET /admin/rate-plans                         | `serviceZoneId`, `serviceType` (sólo LOCAL_DELIVERY), `status` (DRAFT/ACTIVE/INACTIVE), paginación. Incluye bandas        |
| GET /admin/rate-plans/:id                     | Plan con bandas ordenadas por distancia, incluidos históricos                                                             |
| POST /admin/rate-plans                        | `{serviceZoneId,serviceType,quoteValidityMinutes,bands?}`. La moneda se hereda de la zona                                 |
| POST /admin/rate-plans/:id/clone              | Copia TTL y bandas en la siguiente versión DRAFT sin tocar el original                                                    |
| PATCH /admin/rate-plans/:id                   | Sólo `{quoteValidityMinutes}` de un DRAFT; ACTIVE/INACTIVE responden 409 `RATE_PLAN_NOT_EDITABLE`                         |
| PUT /admin/rate-plans/:id/bands               | Sustituye todas las bandas de forma atómica. **Metros enteros**, semántica `[min, max)`                                   |
| POST /admin/rate-plans/:id/validate           | Informe de huecos, solapes y montos inválidos. No modifica el plan                                                        |
| POST /admin/rate-plans/:id/activate           | DRAFT válido → ACTIVE y la ACTIVE anterior → INACTIVE. 422 `RATE_PLAN_INVALID`, 409 `RATE_PLAN_NOT_ACTIVATABLE`           |
| POST /admin/rate-plans/:id/deactivate         | ACTIVE → INACTIVE sin reemplazo                                                                                           |
| GET /admin/delivery-quotes                    | `publicId` (`MQ-\d{6,}`), `deliveryRequestPublicId`, `integrationClientId`, `serviceZoneId`, `status`, `createdFrom/To`   |
| GET /admin/delivery-quotes/:publicId          | Snapshot completo con RatePlan/RateBand aplicados, `routingProvider` y timestamps                                         |
| GET /admin/delivery-requests/:publicId/quotes | Historial de Quotes de cualquier solicitud                                                                                |

`amount` es string con 2 decimales (`NUMERIC(14,2)`): se formatea, **nunca se recalcula**. `status` de una Quote es el **estado efectivo**: una OFFERED con `expiresAt` vencido llega como EXPIRED. La superficie admin de Quotes es de **sólo lectura**: no existe creación, aceptación, edición ni eliminación administrativa, y la UI no ofrece esos botones.

### Unidades

El backend trabaja en **metros enteros** y la UI muestra **kilómetros**. `metersFrom()` acepta hasta 3 decimales y redondea (`2 km → 2000`, `7.5 km → 7500`); `km()`/`kmValue()` hacen el camino inverso. La conversión se verifica en `pricing-api.test.ts` y contra el backend real en `verify-pricing.mjs`.

### Errores

`ApiError` ahora conserva `code` (el `DomainException` estable del backend) y `details` (el arreglo `errors` de una validación 400). El mensaje mostrado se resuelve por `code` → mensaje conocido → estado HTTP → genérico; **nunca** se refleja texto arbitrario del backend. Se añadieron 422 y 503 al mapa de estados y la traducción de `SERVICE_ZONE_*`, `RATE_PLAN_*`, `QUOTE_*`, `OUT_OF_SERVICE_AREA`, `CROSS_ZONE_NOT_SUPPORTED`, `ROUTE_NOT_FOUND`, `ROUTING_UNAVAILABLE`, `DISTANCE_NOT_SUPPORTED` y `RATE_CONFIGURATION_UNAVAILABLE`. Un fallo de cotización nunca se representa como `$0`.

`bandError()` traduce los diagnósticos de bandas, que son plantillas generadas por `rate-bands.ts` (huecos, solapes, límites, montos, moneda), y convierte sus metros a kilómetros. Lo que no reconoce cae en una frase genérica: el texto crudo no llega a pantalla.

## UI y arquitectura

| Ruta                       | Pantalla                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| /service-zones             | `ServiceZonesPage`: filtros servidor en URL, tarifa activa por zona, paginación, estado vacío    |
| /service-zones/new         | `ServiceZoneNew`: código, nombre, moneda y cobertura GeoJSON                                     |
| /service-zones/:id         | `ServiceZoneDetail`: resumen, cobertura, versiones de tarifa y activación                        |
| /rate-plans/:id            | `RatePlanDetail`: resumen, vigencia, bandas (editor sólo en DRAFT), validación y activación      |
| /delivery-quotes           | `QuotesPage`: filtros servidor en URL, estados traducidos, paginación, estado vacío              |
| /delivery-quotes/:publicId | `QuoteDetail`: precio, distancia, duración, zona, tarifa, estado, vigencia e información técnica |

- `src/pricing/`: `types.ts` (contrato), `service.ts` (única capa HTTP sobre `api()`), `queries.ts`, `format.ts` (unidades, moneda, traducción de bandas, GeoJSON), `zones.tsx` y `rate-plans.tsx`.
- `src/quotes/`: `types.ts`, `service.ts`, `queries.ts`, `format.ts` y `pages.tsx`, que además exporta `RequestQuotes`, la sección que V1.6 agrega al detalle V1.5 de solicitud.
- Compartidos: `Badge` acepta `label` para el género correcto de cada dominio (`Activa`, `Borrador`, `Ofrecida`); es opcional y compatible con V1.3–V1.5.
- Sidebar: `Cotizaciones` y `Zonas de servicio` después de `Solicitudes`, sólo SUPER_ADMIN. Las tarifas se alcanzan desde su zona, que es donde viven en el modelo. Rutas dentro de `Protected roles={['SUPER_ADMIN']}`: una URL escrita a mano muestra 403 sin llamar a la API.
- Sólo aparece `LOCAL_DELIVERY`, el único valor del enum del backend. No hay formularios ni botones para INTERCITY o FREIGHT.
- Sin editor cartográfico: la cobertura se muestra como bounding box, tipo de geometría, número de posiciones y el GeoJSON; se reemplaza completa y sólo con la zona inactiva. El frontend comprueba la forma (Polygon/MultiPolygon con coordenadas `[longitud, latitud]`); anillos cerrados, área y autointersecciones los valida el backend.
- ACTIVE e INACTIVE no muestran edición y el backend sigue siendo la autoridad: `verify-pricing.mjs` comprueba que un `PUT /bands` directo sobre una versión histórica responde 409.

### Quote TTL ≠ calendario del servicio

`quoteValidityMinutes` determina **cuánto tiempo puede aceptarse el precio**, no cuándo se realizará el servicio. La UI lo dice en el panel de vigencia del plan y en el detalle de cada Quote. Una Quote ACCEPTED congela su precio y no se presenta como expirada después de `expiresAt`.

### Contexto económico

`Valor de mercancía` (V1.5) y `Costo de entrega` (V1.6) se muestran en paneles separados y no se suman: el backend todavía no define un total operacional, así que la UI no lo inventa. Aplica igual a `PREPAID` y a `COURIER_ADVANCE`.

Variables: `E2E_ZONE_CODE` (opcional; por defecto la primera zona ACTIVE), `E2E_WEB_URL`, `E2E_API_URL`, `E2E_BROWSER_CHANNEL` (p. ej. `msedge` si no están instalados los navegadores de Playwright). ## Hallazgos

1. El listado de zonas no incluye `boundary` ni la tarifa activa; la columna «Tarifa activa» se resuelve con una consulta por fila acotada a `pageSize=1`, no con el detalle completo de cada zona.
2. El backend devuelve el detalle de bandas inválidas en `errors` sólo para 400. Un 422 `RATE_PLAN_INVALID` trae el informe concatenado en `message`, que no se refleja: el panel de Validación usa `POST /validate`, que sí devuelve la lista, para explicar qué corregir.
3. `POST /rate-plans/:id/validate` es de sólo lectura por contrato, así que la UI lo consume como consulta y lo revalida al cambiar `updatedAt`.
4. `npm run format:check` falla en todo el repositorio en esta copia de trabajo Windows: git entrega CRLF y el `endOfLine` por omisión de Prettier es `lf`. Afecta también a archivos no tocados por V1.6 (`vite.config.ts`, `tsconfig.json`); el contenido de los archivos nuevos sí está formateado con Prettier.
